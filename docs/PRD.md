# 智能提醒系统 — 产品需求文档 (PRD)

> 版本 1.0 · 2026-05-25
> 产品目标：通过智能提醒提升学生每日学习任务完成率

---

## 1. 背景与问题

### 1.1 业务背景

我们是 AI 教育产品。学生在 App 内完成每日学习任务（看课、做题等）。部分学生不会主动打开 App 完成任务，导致学习中断、效果下降。

### 1.2 现状数据

| 指标 | 数值 |
|------|------|
| DAU | 50 万 |
| 付费学生（有每日任务） | 30 万 |
| 当天未完成任务即离开 | ~40%（12 万） |
| 现有推送到达率 | ~60%（部分用户关通知权限） |
| 推送打开率 | **8%** |
| 打开后任务完成率 | 45% |

### 1.3 当前推送的问题

- **时间固定**：每天 18:00 统一发送，无视用户个人空闲时段
- **内容固定**：所有用户收到相同文案「你还有学习任务未完成」
- **频次单一**：每天仅 1 次，错过无后续
- **无个性化**：不分用户类型、行为习惯、学习进度

## 2. 用户分层模型

### 2.1 三层分类

| 类型 | 占比 | 特征 | 策略核心 |
|------|------|------|---------|
| **自律型** SELF_DRIVEN | 40% | 每天主动完成任务 | 轻提醒、不骚扰、进度鼓励 |
| **需提醒型** NEED_REMINDER | 35% | 需推送才完成 | 智能定时、个性化文案 |
| **流失倾向型** DROPOUT | 25% | 提醒也不一定来 | 多渠道触达、激励干预 |

### 2.2 分层依据

| 条件 | 判定结果 |
|------|---------|
| 近 7 天完成率 ≥ 80% | 自律型 |
| 近 7 天完成率 40%–80% | 需提醒型 |
| 近 7 天完成率 < 40% 或 连续 3 天未完成 | 流失倾向型 |
| 注册 < 7 天 或 数据不足 | 冷启动（默认需提醒型） |

### 2.3 用户行为时刻

| 时段 | 活跃占比 | 场景 |
|------|---------|------|
| 16:00–18:00 | 35% | 放学后 |
| 19:00–21:00 | 45% | 晚饭后 |
| 日均在线时长 | ~25 分钟 | 碎片化使用 |

## 3. 业务目标

### 3.1 核心指标

| 指标 | 当前 | 目标 | 说明 |
|------|------|------|------|
| 每日任务完成率 | 60% | **75%** | 北极星指标，关联学习效果 |
| 推送打开率 | 8% | **15%**+ | 推送有效性的直接度量 |
| 流失率（7 日未打开） | ~30% | **< 20%** | 留存健康的间接指标 |
| 推送到达率 | ~60% | **> 80%** | 基础设施质量指标 |

### 3.2 估算模型

```
当前：30万付费 × 60%完成率 = 18万学生/天完成任务
目标：30万付费 × 75%完成率 = 22.5万学生/天完成任务
增量：+4.5万学生/天

打开率提升路径：8% → 15%（+87%）
  - 智能时段：预计 +40% 打开率（8% → 11.2%）
  - 个性化文案：预计 +25% 打开率（11.2% → 14%）
  - 动态频次：预计 +10% 打开率（14% → 15.4%）
```

## 4. 功能需求

### 4.1 用户故事

| ID | 角色 | 故事 | 优先级 |
|-----|------|------|--------|
| US-01 | 自律型学生 | 我想在学习完成后收到进度反馈，了解自己超过多少同学 | P1 |
| US-02 | 需提醒型学生 | 我想在最佳学习时间收到提醒，不要在我忙的时候打扰我 | P1 |
| US-03 | 流失倾向型学生 | 我想在连续未学习时收到有激励的推送，重新激发学习动力 | P1 |
| US-04 | 所有学生 | 我可以设置自己的推送偏好（开关、时段、频率） | P1 |
| US-05 | 产品经理 | 我可以创建 A/B 实验对比不同推送策略的效果 | P2 |
| US-06 | 产品经理 | 我可以看到推送大盘数据：打开率、完成率、分层分布 | P2 |
| US-07 | 运营 | 我可以管理推送模板，针对不同分层配置不同文案 | P2 |
| US-08 | 所有学生 | 我可以在线收到微任务的即时完成反馈 | P2 |

### 4.2 功能模块

#### 智能提醒引擎（核心）

```
模块拆解：
  1. 时机决策模块
     - 输入：用户分层、活跃时段、历史打开时间、当前在线状态
     - 输出：最佳推送时间
     - 算法：
       a. 有历史打开记录 → 取该用户历史打开时间的 P50
       b. 有活跃时段 → 取时段中点前 30 分钟
       c. 冷启动 → 按分层默认时间
       d. 用户在线 → 跳过推送（不骚扰）

  2. 内容生成模块
     - 输入：用户分层、未完成任务数、完成率、排行榜位置
     - 输出：推送标题 + 正文
     - 策略：模板变量填充（预留 LLM 接口）

  3. 频次控制模块
     - 输入：用户分层、当前推送次数、上次推送时间、当前时间
     - 输出：允许/拒绝推送
     - 检查项：每日限额、最小间隔、免打扰时段、在线状态
```

#### 各分层推送策略

| 维度 | 自律型 | 需提醒型 | 流失型 |
|------|--------|---------|--------|
| 每日上限 | 0–1 条 | 1–2 条 | 2–3 条 |
| 推送时机 | 任务完成时 | 活跃时段前 30min | 18:00 + 20:00 |
| 文案风格 | 进度鼓励 | 紧迫感 | 激励唤醒 |
| 二次推送 | 无 | 1h 未完成补一次 | 次日 10:00 再加 |
| 免打扰 | 21:30–07:00 | 21:30–07:00 | 21:30–07:00 |

### 4.3 微任务（行为心理学设计）

**设计意图**：降低任务启动的心理门槛。

```
一个每日任务拆分为 3–5 个微任务，每个 3–5 分钟可完成。
完成一个微任务 → 即时正反馈（前端动画）
心理学原理：「一旦开始，就更容易继续」（Zeigarnik Effect）
```

## 5. 非功能需求

| 需求 | 指标 | 说明 |
|------|------|------|
| 推送延迟 | < 5 分钟 | 从决策到发送的端到端延迟 |
| 频控响应 | < 100ms | Redis 检查必须在毫秒级 |
| 批量推送 | 1000 条/秒 | 高峰期吞吐量 |
| 系统可用性 | 99.9% | 推送不可用影响学习连续性 |
| 数据安全 | 用户数据不出服务器 | 自建 A/B 测试不依赖第三方 |

---

## 6. 成功标准

```
目标指标（上线后 4 周）：
  - 每日任务完成率：≥ 75%
  - 推送打开率：≥ 15%
  - 7 日未打开用户占比：< 20%

护栏指标（不能恶化）：
  - 通知关闭率：不能上升（当前 ~40% 已关，需保持或降低）
  - App 卸载率：不能上升
```

## 8. 未实现（后续规划）

- **LLM 推送文案**：用 AI 生成个性化文案，用小流量 A/B 测试对比模板
- **社交提醒**：学习小队、排行榜、同桌互催
- **家长端联动**：家长看学习时长和完成率，关心而非告警
- **Widget 桌面组件**：锁屏/桌面显示今日任务进度
- **多通道降级**：推送连续失败 → 降级到短信/微信模板消息
